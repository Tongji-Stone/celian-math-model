# 方案 B 模型说明

脚本：`src/A/task3_pbt_batterygpt_fusion.py`

## 1. 为什么是「融合」而不是加载两个官方大模型

PBT 与 BatteryGPT 的公开权重吃的是圈内电压–电流（或寿命标签），赛题附件只有按圈的 `SOH_smooth` / IR / T / 充电时间。因此本方案在**结构上**对齐两篇论文的路径，用题目数据从头训练：

- **PBT**：跨电池、协议条件门控、寿命标量头
- **BatteryGPT**：生成式预训练 + 未来 SOH 轨迹头
- **方案 B**：共享骨干、双头多任务、一致性损失

## 2. 输入

序列（1–150 圈）：SOH、ΔSOH、IR、Tavg、充电时间、cycle/200。  
静态：\(C_1,Q_1,C_2\)、初始容量、平均充电时间/IR/温度、第 150 圈 SOH、近段斜率、同策略其他电池斜率。

## 3. 结构

```text
序列 → Transformer 编码器
静态 → MLP
         ↓ 相加
      双专家 MoE（协议门控）
         ├─ 轨迹头：近段线性基线 + 残差 → SOH(151–200)
         └─ 寿命头：log N_EOL
一致性：由轨迹末段斜率外推的寿命 ≈ 寿命头
```

## 4. 训练

1. 掩码重建 SOH（自监督，不看 151–200）。
2. 留一电池：在其余 39 块上微调双头；被留出块只给 1–150。
3. 寿命伪标签：用该训练块真实 150→200 斜率外推到 SOH=0.80（不是实测寿命）。
4. 全部 40 块再训一版，用于 9 块测试电池预报。

## 5. 输出

- `output/` 验证表与报告
- `figures/` 对照图
- `weights/fusion_final_all40.pt` 全样本权重
- `比较.md` 与近段线性的优劣
